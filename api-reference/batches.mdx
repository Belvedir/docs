`/api/v1/route/batches` runs deferred bulk inference in the OpenAI chat-completions shape, with results within 24 hours. Batches bill at the batch rate; the Pricing page lists every batch rate under **Batch inference**. Batches are not routed: every request names its model.

## Create a batch

`POST /api/v1/route/batches` with `{"requests": [...]}`. Each request carries a unique `custom_id` (1 to 64 characters) and a `body` in the OpenAI chat-completions shape: messages, tools, `response_format` with a JSON schema, images (base64 data URLs included). Streaming is not supported.

```bash
curl -X POST https://platform.belvedir.ai/api/v1/route/batches \
  -H "Authorization: Bearer $BELVEDIR_API_KEY" -H "Content-Type: application/json" \
  -d '{"requests":[
    {"custom_id":"doc-1","body":{"model":"anthropic/claude-sonnet-5","max_tokens":300,
      "messages":[{"role":"user","content":"Summarize: ..."}]}},
    {"custom_id":"doc-2","body":{"model":"gpt-5.2",
      "messages":[{"role":"user","content":"Summarize: ..."}]}}
  ]}'
# → {"id":"<batch-id>","object":"batch","status":"in_progress","request_count":2,
#    "providers":[{"provider":"anthropic","status":"in_progress","request_count":1},
#                 {"provider":"openai","status":"in_progress","request_count":1}], ...}
```

Every result is an OpenAI `chat.completion` regardless of provider; for Anthropic models, `cache_control` markers and a `thinking` config on the body are honored. One batch can mix providers and is returned as one result list.

**Anthropic-native shape**: a request may send `{"custom_id", "params"}` instead of `{"custom_id", "body"}`: the same wire shape Anthropic's own Message Batches API takes, forwarded verbatim (`cache_control`, `thinking`, native content blocks intact). That request's result carries the **native Anthropic message** instead of a translated `chat.completion`. The two shapes can mix in one batch. Native `params` are accepted for Anthropic models and the hosted open models with a batch tier, not for OpenAI ids, and they refuse every Anthropic server tool, web search included.

**Idempotency**: pass a top-level `idempotency_key` (up to 128 characters, unique per project) with the submission. A retried submit returns the existing batch instead of creating a second one.

## Models and caps

| Provider | Identifiers | Requests per batch |
| --- | --- | --- |
| Anthropic | `anthropic/*` | 100,000 |
| OpenAI | `gpt-*`, `openai/*` | 50,000 |
| Hosted open models with a batch tier | `zai-org/GLM-5.2-FP8`, `moonshotai/Kimi-K2.6`, `google/gemma-4-31B-it` | 1,000, and about 2 MB serialized, whichever comes first |

Every model in a batch must be a priced model (the Pricing page lists them; an unpriced id, `"auto"`, or a model without a batch tier is refused with `400` at submit). A batch naming a Chinese-lab model on a project with **Chinese models** off is refused with `403` at submit. The catalog is on [Available models](/inference/models).

## Large submissions

Inline request bodies cap at about 4.5 MB per request (`413` beyond it). For larger submissions, use the upload flow:

1. `POST /api/v1/route/batches/uploads` returns `201` with `{object, upload_url, expires_in_seconds}`.
2. `PUT` the full submission JSON (`{"requests": [...]}`) to `upload_url` with `Content-Type: application/json`.
3. `POST /api/v1/route/batches` with `{"input_object": "<object>"}` (plus `idempotency_key` if you use one).

The response is identical to an inline submission. The signed `upload_url` is valid for 2 hours (`expires_in_seconds: 7200`); an object uploaded but never submitted is purged after 48 hours. Upload requests share the submission rate limit.

## Status

`GET /api/v1/route/batches/{id}` returns the batch's current state. Most batches finish in minutes; the providers guarantee 24 hours, and a batch you stop polling still completes on its own. A partial failure runs the surviving provider portions and reports the failed portion, with its error, on the status.

| Field | Meaning |
| --- | --- |
| `status` | `in_progress`, `ended`, or `failed` (a canceled batch ends as `ended` with a `canceled_count`; `failed` means every provider portion was refused) |
| `request_count` | requests submitted |
| `providers` | per-provider status and request count |
| `succeeded_count`, `errored_count` | results so far; `canceled_count` and `expired_count` appear when relevant |
| `created_at`, `ended_at` | timestamps |
| `results_url` | present once results are ready |

```bash
curl https://platform.belvedir.ai/api/v1/route/batches/<batch-id> \
  -H "Authorization: Bearer $BELVEDIR_API_KEY"
```

## Results

`GET /api/v1/route/batches/{id}/results` returns JSONL by default: one result object per line, in any order (`409` while the batch is still in progress). The batch id and status ride the `x-belvedir-batch-id` / `x-belvedir-batch-status` headers, and `x-belvedir-results-format` stamps the format served.

```bash
curl https://platform.belvedir.ai/api/v1/route/batches/<batch-id>/results \
  -H "Authorization: Bearer $BELVEDIR_API_KEY"
# → {"custom_id":"doc-1","status":"succeeded","model":"anthropic/claude-sonnet-5","cost":0.00021,"response":{...}}
# → {"custom_id":"doc-2","status":"errored","response":null,"error":{"message":"..."}}
```

Other formats, for code that keeps a provider's own results parser:

| Query | Returns |
| --- | --- |
| `?format=anthropic` | Anthropic's exact results JSONL (batches submitted entirely as native `params`) |
| `?format=openai` | OpenAI's exact batch-output JSONL (batches submitted entirely as OpenAI bodies) |
| `?format=json` | one `{"object":"list","batch_id":"...","status":"...","data":[...]}` envelope, for small batches |

A batch that mixes shapes gets `400` for the provider formats. Results are kept for 29 days after the batch ends, then purged: the results endpoint answers `410` after that, while the batch's counts and spend stay on the status endpoint.

## Cancel

`POST /api/v1/route/batches/{id}/cancel` forwards the cancel to the providers. Requests that already completed still return results and still bill; everything not yet run comes back `canceled` in the results list and is not billed. Canceling twice, or canceling an ended batch, returns the batch's current state.

```bash
curl -X POST https://platform.belvedir.ai/api/v1/route/batches/<batch-id>/cancel \
  -H "Authorization: Bearer $BELVEDIR_API_KEY"
```

## List

`GET /api/v1/route/batches` returns the project's 50 most recent batches, newest first.

## Anthropic SDK batch methods

With the Anthropic client pointed at `baseURL: "https://platform.belvedir.ai/api"`, `client.messages.batches.create / retrieve / results / cancel / list / delete` run against `/api/v1/messages/batches` unchanged. That facade speaks Anthropic's Message Batches wire shapes (batch objects with `processing_status` and `request_counts`, results as their exact JSONL, cursor pagination with `limit` / `after_id` / `before_id`) over the same batch tier: same caps, pricing, cancellation semantics and 29-day retention; its results endpoint answers `400` while the batch is in progress and `404` once results have expired. `DELETE /api/v1/messages/batches/{id}` removes an ended batch and its stored results outright, so later retrieves `404`; deleting a batch that is still in progress returns `400` (cancel it first).

The facade honors the `Idempotency-Key` request header the Anthropic SDKs send automatically (up to 255 characters of letters, digits, `_ . : -`; a body `idempotency_key` works too). Pass `idempotencyKey` in the SDK's request options to set it yourself.

The facade also accepts `{"input_object": "<object>"}` from the [upload flow](#large-submissions) for larger submissions.

## Billing

Batches bill at the batch rate when they end, attributed to the calling API key and shown as "Router (batch)" on the usage page. If your organization's balance cannot cover the batch's estimated cost (request text plus `max_tokens` at the batch rate), submission returns `402` with the estimate: add credits, turn on pay as you go, or split the batch.

A submission whose every provider portion is refused returns `502` with the provider's error and bills nothing.

## Limits and errors

| Limit | Value |
| --- | --- |
| Submissions and upload requests | 30 per minute per API key, burst 30 (`429`) |
| Status polls | 60 per minute per API key, burst 120 (`429`); results reads are not limited |
| `custom_id` | 1 to 64 characters, unique within the batch |
| `idempotency_key` | up to 128 characters, unique per project |
| Inline body | about 4.5 MB per request (`413`); larger submissions go through the upload flow |

When batch capacity is momentarily full, submission returns a retryable `503`; retry after the `Retry-After` header. The one-page summary of every inference limit is on [Capabilities and limits](/inference/capabilities).
