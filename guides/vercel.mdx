The Belvedir SDK is built on OpenTelemetry and needs the Node.js runtime. A route declared with `export const runtime = "edge"` runs untraced: you'll see an `initialize() failed; the app will run untraced` error in the logs and no spans. Use the Node.js runtime for any API route that makes LLM calls:

```ts
export const runtime = 'nodejs'
```

## Flush before the function returns

Vercel functions can freeze or exit as soon as the response is sent, before batched spans export, so `await flush()` at the end of every handler that makes LLM calls; see [Flush on serverless](/sdk/configuration#flush-on-serverless).

## Keep the SDKs external

In Next.js, list your LLM SDKs and `belvedir` itself in `serverExternalPackages`, or a route that bundles its own copy flushes an uninitialized duplicate and spans drop silently; see [Keep LLM SDKs external](/guides/nextjs#keep-llm-sdks-external).

## Environment variables

Set `BELVEDIR_API_KEY` in your Vercel project's **Environment Variables**, then redeploy. See [Environment variables](/guides/environment-variables) for the full list.
