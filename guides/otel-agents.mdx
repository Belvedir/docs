Running an agent you didn't write, like [OpenClaw](https://docs.openclaw.ai) or [Hermes Agent](https://github.com/NousResearch/hermes-agent)? You don't need the Belvedir SDK. The ingest endpoint is a standard OTLP/HTTP trace receiver:

- **Endpoint**: `https://platform.belvedir.ai/api/v1/traces`
- **Auth**: your `bv_live_...` key in an `x-api-key` header (or as a Bearer token)
- **Wire formats**: `http/protobuf` and `http/json`, gzip accepted
- **Content**: spans that follow the OpenTelemetry GenAI conventions (`gen_ai.input.messages` / `gen_ai.output.messages`) show up as full conversations
- **Sessions**: read from a `session.id` or `gen_ai.conversation.id` span attribute. Send the header `x-belvedir-session-from: trace` to treat every trace **that contains an LLM call** as its own session when the exporter doesn't stamp one (housekeeping traces without an LLM span are deliberately not promoted)

Only traces are ingested. There are no metrics or logs endpoints, so turn those signals off or point them elsewhere.

## OpenClaw

Install our [openclaw-belvedir](https://github.com/Belvedir/openclaw-belvedir) plugin. It has zero dependencies (plain JavaScript on Node built-ins, nothing for a security scanner to flag) and, unlike OpenClaw's stock OTel exporter, it stamps OpenClaw's real session identity on every span: a multi-turn conversation becomes one Belvedir session instead of one session per turn, with none of the housekeeping-trace noise.

```bash
openclaw plugins install git:github.com/Belvedir/openclaw-belvedir
```

In `~/.openclaw/openclaw.json`, then restart the Gateway (`openclaw gateway restart`):

```json
{
  "plugins": {
    "allow": ["belvedir"],
    "entries": {
      "belvedir": {
        "enabled": true,
        "config": { "apiKey": "bv_live_..." },
        "hooks": { "allowConversationAccess": true }
      }
    }
  }
}
```

`hooks.allowConversationAccess` is OpenClaw's consent gate for message content: without it the plugin still runs but only structure and timing arrive, and nothing can be segmented into tasks. Set `BELVEDIR_PRIVACY_MODE=true` (or `config.privacyMode`) to send usage and structure only. To confirm the wiring without spending model tokens, the plugin ships a simulator that fires the exact hook sequence of a real two-turn session and prints the session id to look for on the Data pages. Run it from a checkout of the plugin repo:

```bash
git clone https://github.com/Belvedir/openclaw-belvedir && cd openclaw-belvedir
BELVEDIR_API_KEY=bv_live_... node tests/simulate-run.js
```

## Hermes Agent

Install our [hermes-belvedir](https://github.com/Belvedir/hermes-belvedir) plugin. It has zero Python dependencies: nothing to `pip install`, no dependency tree for a security scanner to flag, and few enough lines to review before enabling, as Hermes' security policy asks. It stamps `session.id` on every span, so multi-turn Hermes sessions become Belvedir sessions as-is.

```bash
hermes plugins install Belvedir/hermes-belvedir
hermes plugins enable hermes_belvedir

export BELVEDIR_API_KEY=bv_live_...
```

That's the whole setup. Each turn appears within seconds: the conversation the model saw, its replies, tool calls with results, and token usage per request. Full prompts and responses are captured by default; set `BELVEDIR_PRIVACY_MODE=true` to send usage and structure only. Configuration is environment-first (`BELVEDIR_API_KEY`, `BELVEDIR_ENDPOINT`, `BELVEDIR_PRIVACY_MODE`, `BELVEDIR_CAPTURE_SENDER`, plus `BELVEDIR_DEBUG=true` for stderr diagnostics), with an optional `config.json` next to the installed plugin.

To confirm the wiring without running the agent, the plugin ships a simulator that fires the exact hook sequence of a real two-turn session:

```bash
BELVEDIR_API_KEY=bv_live_... python3 ~/.hermes/plugins/hermes_belvedir/tests/simulate_session.py
```

## Any other OpenTelemetry SDK

The stock OTLP/HTTP trace exporter works with environment variables alone. Add the session header if your agent doesn't set `session.id`:

```bash
OTEL_EXPORTER_OTLP_TRACES_ENDPOINT=https://platform.belvedir.ai/api/v1/traces
OTEL_EXPORTER_OTLP_TRACES_PROTOCOL=http/protobuf
OTEL_EXPORTER_OTLP_HEADERS="x-api-key=bv_live_...,x-belvedir-session-from=trace"
```

Traffic is attributed to the API key in the header like SDK traffic, so you can filter by it on the Data pages. Tasks appear about 30 seconds after a session goes quiet.
