# Belvedir public docs

This is the public documentation site for **Belvedir** (belvedir.ai), built on [Mintlify](https://mintlify.com). Pages are MDX with YAML frontmatter; configuration lives in `docs.json`. Pushes to `main` deploy automatically via the Mintlify GitHub app, and this site HAS served `docs.belvedir.ai` since Aug 2, 2026; production `platform.belvedir.ai/docs` redirects here.

## Source of truth

The platform repo (`Belvedir/belvedir-platform`) is the source of truth for product behavior: its `src/` route handlers and components, `src/lib/agent-skill.ts` (the agent skill, mirrored to `Belvedir/skills`), `src/app/docs/page.tsx` (the legacy in-app docs page, still served on localhost and previews), `loop/README.md`, `loop-py/README.md`, and its `AGENTS.md` and `docs/agents/*.md`. When integration behavior changes there, this site must be updated to match, in the same change. Never document from memory; open the code and check.

## Terminology (July 2026 Belvedir rename; get this right)

- The product is **Belvedir**; the company is Fractal Machine Research, Inc. Never brand pages "Fractal".
- Packages: npm `belvedir`, PyPI `belvedir` (import `belvedir`). The `@belvedir/loop` and `belvedir-loop` names are supported aliases of the same code; docs should say `belvedir`. The legacy `@fractalresearch/loop` / `fractal-loop` packages still work but are deprecated; mention them only as migration notes.
- API keys start with `bv_live_`; legacy `fr_live_` keys remain valid.
- Env vars are `BELVEDIR_*` (`BELVEDIR_API_KEY`, `BELVEDIR_BASE_URL`, `BELVEDIR_RUN_ID`, `BELVEDIR_TASKS_FILE`); legacy `FRACTAL_*` names are set as aliases in benchmark sandboxes only.
- The ingest default is `https://platform.belvedir.ai`; `platform.fractalresearch.ai` is RETIRED (spans sent there are dropped); see the Common Issues entry.
- Task clusters are **task groups** in all user-facing copy (never "clusters", never "training sets", and not "Groups": Groups → Training Sets Aug 10, 2026 → Task Groups Sept 15, 2026; the nav page is **Task Groups**, and "task group" is lowercase in running text). Since Sept 30, 2026 **Training Sets** is a separate page (Data section, below Task Groups) in the ML sense: one training set per task group, the group's successful tasks minus what cleaning removes (evaluation holdout, errored or tool-errored or frustrated or confused tasks, exact duplicates, difficulty outliers). Use "training set" only for that; never for a task group. API tokens keep the old name and are contract, not copy: `tier: "group"`, `tier: "group-record"`, `matched_group`, `x-belvedir-group`. Never rewrite those.
- Curation is the **Cleaning log**; projects are **Projects** (never "instances").
- Loop types: **Harness evolution** (whole-repo GEPA), **Prompt evolution** (scaffolding-only GEPA), **LoRA finetuning**. "Memory harness" and version-style loop names ("loop 0.1.0") are retired. NOTE the historical swap: "Prompt evolution" used to mean the whole-repo loop; today it means the scaffolding-constrained one.
- Autonomy (review vs Auto-PR) is chosen **per loop** in the Training setup wizard; there is no project-wide autonomy switch.
- Billing is per **organization** (Organization Settings → Billing); the pay-as-you-go card belongs to the org owner.
- Training compute: never name the managed training backend's vendor. Say **managed fleet** (the default) versus **private GPUs** (Belvedir's own hardware), matching the platform's copy.
- Page titles and sidebar titles are sentence case; the only exceptions are UI page names used as titles (**Cloud Inference**, **Playground**). Nav groups: Get started, Node SDK, Guides, Inference, Training, Benchmarks, Resources; API Reference: Overview, Tracing, Inference.
- Use the UI's exact control names, bolded: **Token compression** (not "prompt compression" as a control name), **Smart routing**, **Automatic updates**, **Auto reload**, **Chinese models**, **Model training**, **Harness access**, the **Routers** page, the **Cloud Inference** page, **Project Permissions**, **Project settings → Integrations**. Check `src/components/nav.tsx` and the settings components before naming a page or toggle.

## Style preferences

- Use active voice and second person ("you")
- Keep sentences concise: one idea per sentence
- Use sentence case for headings
- Bold for UI elements: Click **Settings**
- Code formatting for file names, commands, paths, and code references
- No em dashes anywhere: prose, tables, code comments, frontmatter. Use a period, comma, colon, semicolon, or parentheses instead. (Copy with em dashes reads as machine-written; this is a house rule across every Belvedir surface.)

## Content boundaries

Competitors read these docs. Document what a user needs to set up, operate, and integrate against; nothing about how Belvedir is built.

- Document the public product surface only: the SDKs, the CLI (`cli.mdx`; the CLI talks to one RPC endpoint, `POST /api/v1/cli`, documented through the CLI rather than as a REST surface), dashboard flows, the public API endpoints, and benchmarks/training/routing behavior and pricing.
- The public API endpoints today, one page each under `api-reference/`: `POST /api/v1/traces` (ingest, OTLP JSON or protobuf), `POST /api/v1/outcomes`, `POST /api/v1/route` (routing decision only), `POST /api/v1/route/chat/completions` (OpenAI-compatible inference), `POST /api/v1/route/embeddings`, `/api/v1/route/batches` (create, list, status, results, cancel, plus `/uploads` for large submissions), the Anthropic Messages passthrough `POST /api/v1/messages`, and its batch facade `/api/v1/messages/batches`. Any new public endpoint gets its own page and a line in `api-reference/overview.mdx`.
- NEVER name the vendors Belvedir itself runs on or buys from: no Sail / Sail Research, no OpenRouter as our upstream, no Modal as our sandbox, no Porter, no Vercel as our host, no Supabase, no training-backend vendor. Say "hosted open models", "Belvedir's batch tier", "an isolated container", "Belvedir's managed workspace", "managed fleet" / "private GPUs". A vendor name is allowed only when the user supplies that vendor's own credential (their Modal tokens for BYO Harbor runs, their Together account for a fine-tune deploy, their OpenRouter or Vercel AI Gateway key). Model MAKERS (Anthropic, OpenAI, xAI, Google, Qwen) are fine.
- No hostnames other than `platform.belvedir.ai` and `docs.belvedir.ai`.
- No algorithm internals: no routing thresholds, confidence bounds, similarity floors, shadow/self-certification mechanics, compression thresholds, optimizer step sequences or scoring tricks. State what the product does and what the user controls. Same for mechanism explanations in general: no routing-decision rules (what counts as hard, what escalates, how conversation is detected), no retry or fallback internals beyond the header values a user can observe, no judge/verifier grading mechanics, no provider-selection logic, no reservation/settlement internals, no "how imports resume". A page says what the user sets, sends, sees, and gets billed for, and nothing about the processing in between unless the user needs it to debug. Optimizer designs are named as the wizard names them (Loop 2 diagnose and repair, Loop 1 GEPA), one sentence each.
- No billing mechanics: no multipliers, discounts, margins, "at cost", sweeps, reservations internals. "Billed per token at the rates on the Pricing page."
- No internal component names in prose (worker, optimizer, segmenter, compressor, pipeline, sweep, batch gateway), no database schema, migrations, internal env vars, admin tooling, quotas that only exist to protect infrastructure, or sandbox hardening lists.
- No changelog tone: no "since 0.3.1", "used to", "before that", dates. Describe current behavior. Legacy-package and old-version pitfalls live ONLY on `migrating-from-fractal.mdx`.
- One canonical home per fact; other pages link in one sentence. Canonical homes: init order + `instrumentModules` → `sdk/installation`; `flush()` + SDK env vars + OS shell syntax → `sdk/configuration`; what auto-instrumentation captures (the capture table) → `sdk/supported-providers`; the `instrumentation.ts` snippet, `serverExternalPackages`, the Node runtime and Vercel deploys → `guides/nextjs`; the AI SDK pitfall + Vercel AI Gateway → `guides/ai-sdk`; plugin env vars → `guides/otel-agents`; outcomes → `api-reference/outcomes`; the router base-URL swap → `inference/route-your-calls`; **Smart routing** / **Automatic updates** / tiers / the machine-shaped-work rule → `inference/mixture-of-models`; catalog → `inference/models`; limits + forced-tool-choice on Fable 5.1 / Opus 5.5 → `inference/capabilities`; registering your own endpoints → `inference/hosted` (the **Cloud Inference** page, nothing else); tracing local or third-party hosted endpoints → `inference/local-models`; retention + **Chinese models** + training gates → `data-handling`; holdout, training-set cleaning, fine-tune test sessions and deploys → `training/overview`; the "Not yet available" preset list + harness contract → `benchmarks/overview`; Harbor export, local runs, managed workspace vs own Modal account → `benchmarks/harbor`; "~30 seconds after a session goes quiet" → `how-it-works`; troubleshooting → `troubleshooting/common-issues` (symptom → fix only; no FAQ; the symptom set is mirrored in the platform and must stay in sync); legacy packages and old-version bugs → `migrating-from-fractal`. Retired pages redirect in `docs.json`: `/guides/vercel`, `/guides/vercel-ai-gateway`, `/guides/environment-variables`, `/troubleshooting/faq`.
- `sources/` holds scraped reference material, not documentation pages (Mintlify ignores it via `.mintignore`).
