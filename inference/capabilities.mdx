Belvedir serves inference on four surfaces behind the same `bv_live_` API key. The request and response contracts are in the API reference, linked per surface.

## The four surfaces

| Endpoint | Speaks | Use it for |
| --- | --- | --- |
| [`POST /api/v1/route/chat/completions`](/api-reference/chat-completions) | OpenAI chat completions | Live inference, routed (`"auto"`) or anchored on the model your code names |
| [`POST /api/v1/messages`](/api-reference/messages) | Anthropic Messages API, untranslated | Claude traffic that leans on native features: prompt caching, thinking, beta headers, the Claude Agent SDK |
| [`POST /api/v1/route/embeddings`](/api-reference/embeddings) | OpenAI embeddings | OpenAI `text-embedding-*` models |
| [`/api/v1/route/batches`](/api-reference/batches) | OpenAI chat bodies, or Anthropic-native params | Deferred bulk work at the batch rate, results within 24 hours |

A fifth endpoint, [`POST /api/v1/route`](/api-reference/route), makes the routing **decision only** and executes nothing: use it when your own code runs the model (local models, your own provider accounts).

## What each surface supports

| Capability | Chat completions | Messages passthrough | Batches |
| --- | --- | --- | --- |
| Streaming | Yes: SSE passed through byte for byte, usage on the final chunk | Yes: Anthropic's native event stream, untouched | No: `stream: true` is rejected with `400` |
| Tool calling | Yes, passed through unchanged | Yes, native | Yes |
| Structured output | Yes: `response_format` passes through | Yes: `output_config`, native | Yes: `response_format` json_schema is translated for Anthropic models |
| Images in prompts | Yes, wherever the upstream model supports them | Yes, native content blocks | Yes, including base64 data URLs |
| Thinking / reasoning controls | Yes, translated to what the serving model accepts; see [reasoning controls](/api-reference/chat-completions#reasoning-controls) | Yes, never injected or stripped | Yes: a `thinking` config survives translation |
| Prompt caching | Provider-dependent; cached tokens bill at the cache-read rate | Yes: `cache_control` reaches Anthropic unmodified | Yes: `cache_control` markers survive |
| Routing (`"auto"`, tiers, task groups) | Yes, while **Smart routing** is on (the default); off means every call serves exactly the model it names | No: model-pinned by design | No: every request names its model |
| Session pinning | Yes: `x-session-id` header or `session_id` body field | No | Not applicable |
| **Token compression** | Yes, per-project toggle, on by default | No: the body is never touched | No |
| Per-call cost | `usage.cost` on the body and the `x-belvedir-cost` header | `x-belvedir-cost` header on non-streamed calls only; streamed calls carry no cost header | Per-result `cost` in the results list |

What **Smart routing** and **Automatic updates** change is on [Model routing](/inference/mixture-of-models).

## Models

The catalog with identifiers, batch tiers, and the rules for local, fine-tuned, and your own registered models is on [Available models](/inference/models); the Messages passthrough accepts Claude models plus the open models listed on [Messages](/api-reference/messages#models).

## What Belvedir cannot do

- **Anthropic Managed Agents / Agent API sessions** run their inference inside Anthropic's own orchestration; there is no base URL to override, for Belvedir or anyone else. Instrument those workloads with the Belvedir SDK for observability instead.
- **Forced tool choice on Claude Fable 5.1 and Claude Opus 5.5**: both reject `tool_choice: "required"` and named-function choices. On chat completions and in batches Belvedir sends those calls with `tool_choice: "auto"` instead; chat completions says so in `x-belvedir-retry: tool-choice-auto`, a batch result carries no marker, so check batch results for a text answer where you expected a tool call. Name the tool in your prompt and do not assume a `tool_calls` finish. The Messages passthrough is untranslated: send `{"type": "auto"}` yourself there. Neither model runs with thinking off.
- **No token-counting, files, image generation, audio, or realtime APIs**: the surfaces above are text-in, text-out chat, embeddings, and batches.
- **Chinese-lab models when the project turned them off** (**Project Permissions**): `403` on every surface, never a silent substitution. See [Data handling](/data-handling).

Per-surface refusals (local and fine-tuned ids without a registered endpoint, OpenAI's pro and codex families, `"auto"` on the Messages passthrough or in batches, server tools, redirects from your endpoint, unpriced ids) are listed in each endpoint's Errors section.

## Operational limits

| Limit | Value |
| --- | --- |
| Request body: chat completions | 1 MB |
| Request body: Messages passthrough | 20 MB |
| Request body: embeddings | 4 MB |
| Request body: batch submission | About 4.5 MB per request inline (`413` beyond it); larger submissions go through the [upload flow](/api-reference/batches#large-submissions) |
| Request body: routing decision (`POST /api/v1/route`) | 128 KB |
| Request body: trace ingest (`POST /api/v1/traces`) | 5 MB, raw or gzip-inflated; up to 1,000 spans and 200 sessions per request |
| Rate: chat, messages, embeddings | 25 requests per second sustained per API key, burst 300 (default; adjustable per organization on request, including unlimited) |
| Rate: batch submissions | 30 per minute per API key, burst 30 (status polls: 60 per minute, burst 120; results reads are not rate-limited) |
| Rate: trace ingest | 2 requests per second sustained per key, burst 120; separately, 20 new session ids per second, burst 2,000 |
| Live call duration | 5 minutes end to end; stream long generations |
| Batch size | 100,000 requests per batch (Anthropic); 50,000 (OpenAI); 1,000 requests and about 2 MB serialized for the hosted open models with a batch tier |
| Batch `custom_id` | 1 to 64 characters, unique per batch |
| Batch `idempotency_key` | Up to 128 characters, unique per project (Anthropic SDK facade: the `Idempotency-Key` header, up to 255 characters of `A-Z a-z 0-9 _ . : -`) |
| Batch results retention | 29 days after the batch ends |
| Session pin lifetime | 24 hours |

Beyond the rate limits the endpoints return `429`; retry after a short backoff. When batch capacity is momentarily full, submission returns a retryable `503`; retry after the `Retry-After` header.
