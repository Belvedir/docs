Belvedir can execute your LLM calls. Point your client at Belvedir and use your Belvedir key in place of the provider key. Two lines change; the client works exactly as before.

## OpenAI-compatible clients

Set the base URL to `https://platform.belvedir.ai/api/v1/route` and the key to your `bv_live_` key.

```ts
import OpenAI from "openai";

const client = new OpenAI({
  baseURL: "https://platform.belvedir.ai/api/v1/route",
  apiKey: process.env.BELVEDIR_API_KEY, // was OPENAI_API_KEY
});

const res = await client.chat.completions.create({
  model: "x-ai/grok-4.6", // unchanged: the model this call already used
  messages,
});
```

```python
from openai import OpenAI

client = OpenAI(
    base_url="https://platform.belvedir.ai/api/v1/route",
    api_key=os.environ["BELVEDIR_API_KEY"],  # was OPENAI_API_KEY
)

res = client.chat.completions.create(
    model="anthropic/claude-sonnet-5",  # unchanged
    messages=messages,
)
```

Do this for every LLM client in your app. Keep the model each call already names and change only the base URL and key. OpenAI ids stay bare (`gpt-5.2`); every other provider's id is written provider-prefixed (`x-ai/grok-4.6`, `anthropic/claude-sonnet-5`). If a call site used a provider-native SDK (xAI, Google), swap it for the OpenAI client pointed at Belvedir and write the model in the prefixed spelling; bare ids are normalized too, so a missed one still routes. The full catalog is on [Available models](/inference/models).

## Anthropic SDK clients

Anthropic SDK call sites keep the Anthropic client and point it at `https://platform.belvedir.ai/api`; requests pass through to the Messages API untranslated. That surface is model-pinned; see [Messages](/api-reference/messages).

```ts
import Anthropic from "@anthropic-ai/sdk";

const client = new Anthropic({
  baseURL: "https://platform.belvedir.ai/api",
  apiKey: process.env.BELVEDIR_API_KEY,
});
```

## What happens

The model your code names is the ceiling: it answers every conversational call. With **Smart routing** on (the default), cheaper tiers may take the machine-shaped work underneath it; turned off, every call serves exactly the model it names. `model: "auto"` hands a call to the project's auto router. The response's `model` field says what ran and the `x-belvedir-*` headers say why; routers, tiers and **Automatic updates** are on [Model routing](/inference/mixture-of-models).

## Billing

Belvedir runs the call and bills your organization per token at the rates on the Pricing page (**Inference → Pricing**), attributed to the calling API key. On the OpenAI-compatible endpoint every response carries `usage.cost`, the amount billed for that call; the Anthropic passthrough reports it in the `x-belvedir-cost` header on non-streamed calls.
